# Feature Specification: LocalHosts Hosts 管理

**Feature Branch**: `001-hosts-manager`  
**Created**: 2026-04-12  
**Status**: Draft  
**Input**: User description: "LocalHosts hosts 管理：加载、展示、启用/禁用、增删改、保存需授权；保留注释行与空行；兼容标准 hosts"

## Clarifications

### Session 2026-04-12

- Q: 本次特性范围的目标平台是什么？ → A: macOS + Windows + Linux
- Q: 禁用条目与“纯注释行”如何区分？（用于解析与开关切换） → A: 仅当注释后内容仍是合法条目（IP + 域名...）才当作可切换的禁用条目；其他 # 开头行一律视为纯注释并保持原样
- Q: 当 hosts 行中同一 IP 后包含多个域名/别名时，列表应如何展示与编辑？ → A: 拆分为多条
- Q: “用户目录存储 + 分组组装 hosts”在本次特性中做到什么程度？ → A: 支持分组，并且可以控制是否进行组装，并把数据存储到用户目录持久化
- Q: 保存到系统 hosts 时的写回策略是什么？ → A: 仅管理标记块
- 术语约定：保存=保存工作区到用户目录；应用=应用到系统 hosts（提权写回）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看与快速切换 Hosts（Priority: P1）

用户打开应用后，系统自动加载本机系统 hosts 文件内容并展示。在“系统hosts”视图中展示系统 hosts 全量内容（包含管理块与块外内容），且始终只读。启动时系统会检查是否具备写入系统 hosts 的权限：若无权限则请求管理员授权；在授权前应用仅允许只读查看，禁止编辑。授权后，用户可以选择分组并编辑分组文本，修改会自动保存并写入系统 hosts。

**Why this priority**: 这是核心价值路径，用户必须先看见当前配置并快速开关，才能完成后续编辑与保存。

**Independent Test**: 在一份包含启用条目、禁用条目（被注释的条目）、注释行与空行的 hosts 文件上，打开应用后能正确展示；切换开关后列表状态立即变化且条目内容不丢失。

**Acceptance Scenarios**:

1. **Given** 系统 hosts 文件存在且包含管理块内条目、管理块外内容、注释行与空行，**When** 用户打开应用，**Then** 系统自动加载并展示管理块内的可编辑条目（包含 IP、域名、备注、状态），且管理块外内容保持只读展示。
2. **Given** 应用启动时检测到无写入权限，**When** 系统弹出授权提示且用户未完成授权，**Then** 应用保持只读查看且右侧文本不可编辑。
3. **Given** 用户完成授权，**When** 用户修改右侧分组文本中的某一行条目或开关状态，**Then** 修改会自动保存并写入系统 hosts，且写入仅影响 LocalHosts 管理块。
4. **Given** 用户刚打开应用或点击“系统hosts”，**When** 右侧展示内容，**Then** 右侧展示系统 hosts 的全量内容并保持只读。

---

### User Story 2 - 管理条目（新增/编辑/删除）（Priority: P2）

用户在应用内管理分组与条目：左侧分组列表保持不变；分组的新增与修改通过弹窗完成。右侧为所选分组的逐行文本输入，不使用表格或字段模型编辑；右侧不提供“新增/删除按钮”，新增与删除通过直接编辑文本完成。用户可选择是否按分组组装生成最终可写入系统 hosts 的内容；所有文本修改默认自动保存并写入系统 hosts。

**Why this priority**: 用户需要在不直接编辑系统文件的情况下完成常见维护操作。

**Independent Test**: 在未保存到系统文件前，新增/编辑/删除操作可被撤销（通过不保存直接退出）且列表始终与内存中的条目集合一致。

**Acceptance Scenarios**:

1. **Given** 用户处于条目列表页，**When** 用户新增一条目并填写 IP、域名、备注后保存到应用内工作区，**Then** 列表出现该条目且默认状态为启用。
2. **Given** 用户已完成授权且选择了某个分组，**When** 用户在右侧文本中新增一行合法条目，**Then** 条目被解析并自动保存与写入系统 hosts。
3. **Given** 用户已完成授权且选择了某个分组，**When** 用户在右侧文本中删除某一行条目，**Then** 对应条目从工作区移除并自动保存与写入系统 hosts。
4. **Given** 用户有多个分组，**When** 用户选择启用/禁用某分组或切换“是否组装”选项，**Then** 用于保存的组装结果随之变化且不影响管理块外内容。

---

### User Story 3 - 授权保存到系统 Hosts（Priority: P3）

用户完成编辑后选择“应用到系统 hosts”，系统在需要写入系统 hosts 文件时请求管理员授权。授权成功后，系统将当前工作区内容写入系统 hosts 文件并可再次加载验证。

**Why this priority**: 保存是闭环，但涉及系统权限，风险更高且需要在前两条路径稳定后再进入。

**Independent Test**: 在授权失败与授权成功两种情况下，系统行为可预测：失败不破坏原文件；成功写入后重启应用仍能加载到一致内容。

**Acceptance Scenarios**:

1. **Given** 用户在工作区修改了条目，**When** 用户点击“应用到系统 hosts”且授权失败或被取消，**Then** 系统不修改系统 hosts 文件，并向用户展示明确的失败原因或取消状态。
2. **Given** 用户在工作区修改了条目，**When** 用户点击“应用到系统 hosts”并完成授权，**Then** 系统将工作区内容写入系统 hosts 文件，且写入后可重新加载并得到一致结果。

### Edge Cases

- hosts 文件不存在、无法读取或权限不足时，系统如何提示并恢复到可操作状态？
- hosts 文件包含不可解析行（例如非标准格式但不是纯注释行）时，系统如何保留并避免破坏原内容？
- 同一条目出现重复域名或重复 IP+域名组合时，系统如何展示与保存？允许重复且不自动去重；列表中重复项按独立条目展示。
- 条目字段包含多余空白、tab、或备注中包含 `#` 时，系统如何解析与回写以保持兼容？
- 当管理块不存在、边界标记缺失或损坏时，系统如何创建/恢复管理块并避免覆盖块外内容？
- 当同一 IP 行包含多个域名时，拆分后的启用/禁用与保存如何保持可预期？
- 是否支持将“管理块外条目”迁移进管理块进行编辑？本期不支持（块外只读展示）。
- 首次使用：系统 hosts 不包含管理块时，应用到系统 hosts 将在文件末尾追加一个完整管理块（块前确保至少一空行）。
- 边界损坏：若只存在 START 或 END 边界，原边界相关内容视为块外内容并原样保留；应用到系统 hosts 时在文件末尾追加新的完整管理块。
- 外部并发修改：应用到系统 hosts 前必须重新读取系统 hosts，以最新块外内容为准，仅更新/写入管理块。
- 写入失败恢复：应用到系统 hosts 写入失败时必须回滚恢复写入前内容，并告知用户是否已恢复成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在应用启动时自动读取当前平台的系统 hosts 文件，并识别 LocalHosts 管理块与块外内容。若读取失败（不存在/不可读/权限不足），系统 MUST 给出可理解的错误提示，并允许用户继续使用工作区（“系统hosts”视图为空或使用上次成功读取的缓存）。
- **FR-002**: 系统 MUST 使用“左侧分组 + 右侧文本编辑器”的方式呈现与编辑管理块内条目：左侧展示分组列表；分组新增与修改 MUST 通过弹窗完成；右侧以逐行文本方式编辑所选分组条目，不使用表格化字段编辑，且右侧不提供新增/删除按钮。不对 hosts 内容做自动脱敏或遮盖（该工具的目标即为本机查看与编辑）。
- **FR-019**: 系统 MUST 提供“系统hosts”视图用于只读展示系统 hosts 的全量内容（包含管理块与块外内容），且该视图不可编辑。
- **FR-020**: 系统 MUST 自动适配当前操作系统的深色/浅色主题（Dark/Light Mode），并对整体 UI 进行视觉优化（如色彩搭配、边框、间距等）以提供更好的使用体验。
- **FR-021**: 系统 MUST 包含一个自定义的应用程序 Logo（AppIcon），且在相关位置（如关于、文档或 UI 中）标注作者信息：作者 `yuzl`，邮箱 `yuzl6@foxmail.com`。
- **FR-003**: 系统 MUST 支持新增条目，且新增条目至少包含 IP 与域名；备注为可选。
- **FR-004**: 系统 MUST 支持编辑现有条目的 IP、域名与备注，并在保存前将修改保留在应用工作区内。备注（comment）允许为空；不允许包含换行；允许包含 `#` 字符并按原样持久化与写回。
- **FR-005**: 系统 MUST 支持删除现有条目，并在保存前将删除结果保留在应用工作区内。
- **FR-006**: 系统 MUST 支持启用/禁用条目；禁用 MUST 通过对该条目对应行进行注释表达，启用 MUST 通过取消对该条目对应行的注释表达。
- **FR-007**: 系统 MUST 在启动时检查是否具备写入系统 hosts 的权限：若无权限 MUST 发起管理员授权流程。授权未完成前，系统 MUST 仅允许只读查看并禁用编辑入口。授权成功后，在本次应用运行期间，系统 MUST 复用该授权结果用于后续写入，避免每次写入都重复弹出授权提示。
- **FR-018**: 系统 MUST 将所有可编辑文本修改视为“默认保存并写入”：用户完成文本修改后，系统 MUST 自动保存工作区到用户目录并自动写入系统 hosts（仅更新 LocalHosts 管理块）。写入失败时 MUST 回滚恢复；授权失败或取消时 MUST 不修改系统 hosts 文件，并以可理解的信息告知用户（至少区分：取消、权限不足、写入失败/回滚失败）。
- **FR-008**: 系统 MUST 定义“合法条目”的判定规则：去除可选的整行注释前缀（`#` + 任意空白）后，以空白分隔 token；第 1 个 token 为 IP（IPv4 或 IPv6 文本），后续至少 1 个 token 为域名/别名（不包含空白与 `#`）。解析必须兼容 tab 与多空格。
- **FR-009**: 系统 MUST 在解析与保存时区分“被注释的禁用条目”和“纯注释行”：仅当 `#` 开头的行在去除注释前缀后仍满足 FR-008 的合法条目规则时，才将其视为可切换的禁用条目；否则一律视为纯注释行并在保存时原样保留。
- **FR-010**: 系统 MUST 支持将“同一 IP 行的多个域名/别名”拆分为多条可编辑条目，并要求保存时以“一域名一行”输出，以便每个域名条目可独立启用/禁用（禁用通过整行注释表达）。
- **FR-011**: 系统 MUST 支持分组：每个条目 MUST 归属到一个分组；用户 MUST 能控制是否按分组组装生成最终用于写入的内容。组装规则：当 composeEnabled=true 时仅输出 enabled=true 的分组；当 composeEnabled=false 时输出全部分组；条目 enabled 始终生效。如果某个分组内没有包含任何条目（即分组为空），则在写入系统 hosts 文件时 MUST 忽略该分组，不输出该分组的边界注释及内容。
- **FR-012**: 系统 MUST 仅写入/更新 LocalHosts 管理块内容；管理块外内容（包括注释行与空行）MUST 原样保留且相对顺序不变。原样保留要求：管理块外逐行文本保持一致（包含空白字符与空行），并保留原文件行尾换行风格（LF/CRLF）；管理块内输出也必须使用与原文件一致的换行风格。
- **FR-017**: 系统 MUST 通过分组边界注释来表达分组范围：写入系统 hosts 的管理块内，每个分组以 `#######<分组名>开始####` 开始，以 `#######<分组名>结束####` 结束，且分组内条目位于两者之间。
- **FR-016**: 系统 MUST 兼容标准 hosts 文件格式；解析与回写 MUST 不引入会导致系统解析失败的格式变化。
- **FR-013**: 系统 MUST 将“不可解析行”视为块外内容：不得误判为可编辑条目；在列表中仅以只读方式展示（可折叠）；本期不支持将其迁移进管理块进行编辑。
- **FR-014**: 系统 MUST 在用户目录中持久化分组、条目与组装开关等工作区数据，以便恢复编辑状态并支持跨平台一致的用户体验。最小持久化字段：`composeEnabled`、`groups(id,name,enabled,order)`、`entries(id,ip,domain,comment,enabled,groupId)`、`version`、`updatedAt`。用户目录路径 MUST 使用平台推荐的应用配置目录，不得硬编码绝对路径。
- **FR-015**: 系统 MUST 不发起任何网络请求，且不得在日志/诊断输出中包含系统 hosts 的具体内容（域名/IP/注释等）；UI 展示仅限本机用户主动查看。

### Key Entities *(include if feature involves data)*

- **HostEntry**: 表示一个可编辑 hosts 条目，包含 IP、域名、备注、启用状态，以及用于无损回写的原始行信息。
- **HostDocument**: 表示一个 hosts 文件的有序内容，包含可编辑条目与不可编辑的原始行（注释行、空行与不可解析行）。
- **WorkspaceState**: 表示应用工作区的持久化状态，存储于用户目录，用于恢复编辑状态并支持后续分组扩展。
- **HostGroup**: 表示条目分组，包含分组名称、启用状态与组装顺序信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在典型 hosts 文件规模（<= 500 行）下，从启动应用到条目列表可交互的时间中位数 <= 1 秒（手工计时，连续 5 次测量取中位数）。
- **SC-002**: 用户在不应用到系统 hosts 的情况下进行新增/编辑/删除/切换/分组/组装开关操作后退出应用，再次打开应用仍能恢复到上次的工作区状态（包含分组顺序与开关状态）。
- **SC-003**: 执行应用到系统 hosts 后，管理块外内容在写入前后保持逐行一致（内容、相对顺序、空白字符与行尾换行风格均不变）；仅 LocalHosts 管理块允许变化。
- **SC-004**: 授权失败或用户取消时，系统 hosts 文件保持不变（可通过写入前后字节级对比或哈希对比判定），且用户能继续在工作区内修改并重试应用。
- **SC-005**: 在应用空闲状态下（打开主界面且无额外操作 30 秒），进程常驻内存占用 < 30MB（使用系统任务管理器/活动监视器观察）。

## Assumptions

- 目标用户为本机开发者/高级用户，理解 hosts 的基本用途，并愿意在保存时进行管理员授权。
- 当同一 IP 行包含多个域名/别名时，系统以“一个域名/别名对应一个可编辑条目”的方式展示与编辑。
- 功能不包含网络访问、远端同步与多设备共享。
- 跨平台一致：条目模型、分组语义、组装规则、管理块格式与写回策略一致；平台差异仅体现在系统 hosts 路径与授权方式。
- 本特性的设计与实现计划文档以中文输出。
