# Research: LocalHosts Hosts 管理

**Feature**: [spec.md](file:///Users/yuzl6/Documents/trae_projects/localHosts-spec-kit/specs/001-hosts-manager/spec.md)  
**Created**: 2026-04-12

## 结论概览

- 平台：macOS + Windows + Linux
- 写回策略：仅管理 LocalHosts 标记块（块外原样保留）
- 注释规则：`#` 开头且去掉前缀后仍可解析为合法条目 → 视为禁用条目；否则为纯注释行
- 多域名：同一 IP 行多个域名拆分为多条可编辑条目；保存时写为“一域名一行”以保证独立开关
- 分组与组装：支持分组、分组开关与顺序；提供“是否按分组组装”开关来决定写入内容
- 存储：用户目录持久化工作区（分组、条目、开关、顺序、最近一次生成结果摘要等）

## 平台 hosts 路径与权限

### 决策

- **macOS**：系统 hosts 路径为 `/etc/hosts`，写入需要管理员授权
- **Linux**：系统 hosts 路径为 `/etc/hosts`，写入需要管理员授权
- **Windows**：系统 hosts 路径为 `C:\Windows\System32\drivers\etc\hosts`，写入需要管理员授权

### 方案

- 读：普通权限直接读取系统 hosts
- 写：采用“生成目标内容 → 写入临时文件 → 管理员授权覆盖写入”的模式，并在覆盖前备份原文件

## 文件解析与无损保留

### 决策

- 系统 hosts 文件拆为两类内容：
  - **块外内容**：LocalHosts 管理块以外的所有行（包含纯注释行、空行、不可解析行、用户自定义内容）
  - **管理块内容**：LocalHosts 标记块内的条目与辅助注释（由本应用负责读写）
- 块外内容在保存时保持原样（内容与相对顺序不变）

### 注释区分规则

- `#` 开头的行，若去掉 `#` 与其后空白后仍能解析为合法 hosts 条目（IP + 1..N 个域名/别名）：
  - 视为“禁用条目”
- 否则：
  - 视为“纯注释行”，不可被开关操作影响，保存时原样保留

## LocalHosts 管理块格式

### 决策

使用明确边界行包裹，便于稳定定位与原样保留块外内容：

```text
# === LocalHosts START ===
# Managed by LocalHosts. Do not edit within this block.
<generated lines>
# === LocalHosts END ===
```

### 方案

- 若系统 hosts 不存在管理块：保存时在文件末尾追加一个管理块（块前确保至少一空行）
- 若管理块存在但边界不完整：不覆盖块外内容；保存时将其视为“块外内容”，并在文件末尾重新追加一个新的管理块

## 多域名拆分策略

### 决策

- 读取时：一行 `IP domain1 domain2 ...` 拆为多条条目（每个域名/别名一条）
- 保存时：统一写回为“一域名一行”

### 理由

- 允许对每个域名进行独立启用/禁用
- 降低回写时的合并复杂度与歧义

## 分组与组装策略

### 决策

支持以下能力：

- 分组（组名、启用/禁用、排序）
- 条目归属分组
- “是否按分组组装”开关：
  - 开启：仅将启用分组的条目组装写入管理块
  - 关闭：忽略分组启用状态，将所有分组的条目统一写入管理块（分组仅作组织用途）

### 组装规则

- 分组顺序决定输出顺序
- 在同一分组内，条目按其创建/编辑后的稳定顺序输出（不做隐式排序）
- 条目开关（enabled）仍然生效：禁用条目以整行注释形式输出

## 用户目录持久化

### 决策

工作区数据持久化到用户目录（跨平台一致），用于恢复未保存状态与分组配置。

### 方案

- 存储位置：使用系统推荐的用户配置目录（例如“用户配置目录/LocalHosts/”）
- 存储内容：
  - 分组列表（名称、顺序、enabled）
  - 条目列表（分组归属、enabled、IP、domain、comment、raw/来源信息）
  - 组装开关（composeEnabled）

## 写入安全与回滚

### 决策

- 覆盖写入前先备份系统 hosts（与写入同目录或用户目录）
- 写入失败时自动恢复原文件

### 理由

- 写入系统文件失败风险高，必须提供可回滚能力以符合“系统文件写入可回滚”原则
